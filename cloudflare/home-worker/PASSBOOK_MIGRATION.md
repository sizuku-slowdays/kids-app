# つうちょうの移行状況

画面・HOMEセッション連携・子ども別の現金/複数ポイント台帳・履歴・交換申請/承認を実装。
`/apps/passbook/?preview=child` と `?preview=admin` は架空データの操作確認画面。実データを書き換えない。
通常画面は `passbook_activation` がない家庭では残高を表示せず操作不可。
HOMEのアプリ一覧は移行照合前に ready にしない。

## 旧保存先の接続

旧銀行とお手伝いは同じ `mama-bank-db`。そのD1のUUIDを確認してから
wrangler.jsoncのd1_databasesに追加：

```json
{"binding":"LEGACY_DB","database_name":"mama-bank-db","database_id":"確認したUUID"}
```

Dashboardだけで追加すると次回Gitデプロイで消える可能性があるので、コード設定も更新する。
旧データの読取は `/api/passbook/legacy-preview`。運営管理者かつ該当家庭管理者に限定。
このコードでは旧D1に書込む処理はない。

## 切替前の必須作業（未実施）

1. 銀行JSON、全chore_logs、rewards、全reward_requestsのエクスポートを非公開R2へ保存。
2. 旧口座ID usagi/kuma等とお手伝いID ane/imouto等を、HOMEの既存child IDへ明示的に対応付け。
   表示名だけでは推定しない。HOMEアカウントは作り直さない。
3. 銀行履歴を符号付き仕訳へ変換、保存済残高との差を開始残高調整として保持。
   日時や履歴形式を実データで確認。元JSONも保持する。
4. chore_logsのポイントを加算、承認済reward_requestsを減算。
   未承認申請は未承認のまま移す。bank_syncedと元IDを保持し、銀行へ二重加算しない。
5. 現金残高/履歴件数、ポイント獲得/使用/予約、交換商品/在庫/申請を照合。
6. 旧アプリの更新を停止し、最終差分を移す。旧公開APIを保護する際、同Workerを使う
   家計簿・学校等のルートは変更しない。旧画面からの上書き・残高二重管理を防ぐ。
7. 照合済みバックアップキーと管理者を passbook_activation に記録して有効化。
   該当HOMEグループの通帳権限を確認し、アプリのpath/statusを設定。

## 権限と記録

- 現金は本人/家庭owner/admin、ポイントは本人/管理者。家庭設定で兄弟姉妹へのポイント閲覧を許可。
- 管理者も自分が所属する家庭だけ。非所属家庭・無効セッションでは取得不可。
- 子どもは自分のリンク済プロフィールだけで交換を申請できる。
- 申請時に残高から予約分を除いて確認。承認はDBトリガー内で在庫と台帳を一緒に更新。
- 台帳は追記のみ、修正は逆方向仕訳。手動登録はevent_idで二重加算を防止。
- ポイント種別は家庭ごとのpassbook_units。将来のいいことポイントを追加しても認証は変わらない。
- 家庭間共有はポイント残高の権限設定とは別に扱う。通帳データを一般共有グループへ公開しない。
