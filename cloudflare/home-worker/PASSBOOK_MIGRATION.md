# つうちょうの移行状況

## 実装済み

- HOME認証で保護された子ども/管理者画面、単位別台帳、交換予約/承認。
- LEGACY_DB (mama-bank-db)から読取。旧DBには書き込まない。
- 運営管理者＋家庭管理者限定の対応付け/取込画面。
- PRIVATE_FILESに旧銀行JSON・全ログ・全交換商品/申請・対応付け・取込計画を保存し、読戻し照合。
- 複数行をJSONで一括INSERTし、D1 batchの一つのトランザクションで取込。
- 銀行履歴と保存済残高との差は開始残高調整。元の日時を含む全JSONを保持。
- ポイント獲得/承認済交換を仕訳化し、未承認申請・商品在庫・bank_syncedを保持。
- ママ等の成人ポイントは個人ユーザーの口座へ保存。子どもプロフィールを作らない。
- 取込後の残高を照合。再取込は二重加算しない。
- 取込後も本番書込を禁止。管理者だけが引継ぎ残高を閲覧できる。
- 旧データが取込時から変わった場合、画面で通知。本番へ自動切替しない。
- 入出金/ポイント登録の理由は任意、よく使う理由をタップで入力。選択対象を維持。

## 本番未完了

実際のログインセッションとHOME子どもIDの選択はユーザー画面で行う。
`/apps/passbook/` の「バックアップと引き継ぎ」から、既存アカウントへ対応付ける。
取込中は旧銀行・お手伝いを操作しない。事前に旧アプリの更新停止方法を準備する。

切替前に必要：
1. 最新の mama-bank-api / otetsudai-api のコードとデプロイ構成を確認。
   同Workerを使う家計簿/学校等のルートは変更しない。
2. 旧銀行の書込/ポイント加算・交換承認・bank-syncを停止し、旧公開APIを保護。
3. 最終ソースと取込済 snapshot_hash が一致することを確認。
   異なる場合は差分移行処理を実装/照合してから切替。今のコードは自動上書きをしない。
4. 口座ごとの残高、銀行履歴件数、ポイント獲得/使用/予約、商品/在庫/申請を実データで照合。
5. 照合済バックアップキー・実行者をpassbook_activationに記録して有効化。
   HOMEアプリpath/statusもこの時点で設定。
6. 子ども・親、URL直アクセス、端末再起動で確認。

まだ本番のactivation・HOME ready化は行っていない。旧アプリはそのまま動く。

## 注意する旧データ

対応先の重複・不明な口座/メンバー・整数でない金額・欠けた履歴は取込を止める。
未承認申請の価格/商品名が変わっている場合や成人の未承認申請がある場合は個別確認が必要。
読取上限は各20,000行、INSERT JSON上限900KB。超えた場合は分割移行を追加する。
取込に失敗してもバックアップは残し、新DBのトランザクションはロールバックする。
公開R2や未認証URL経由でバックアップを配信する処理はない。
