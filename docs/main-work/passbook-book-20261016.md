## APIと残高

`GET /api/passbook/book/accounts` と `GET /api/passbook/book?account=...&from=...&to=...&snapshot=...&after=...`。その他のmethodは405。

- 指定日付はJST。取引の瞬間はjulianday(occurred_at)、同じ瞬間は台帳rowid（登録順）を第2キーにする。文字列表記の時差差異による逆転を避ける。
- 全台帳にSUM(delta)のウィンドウ集計を適用してから、期間・ページ条件を適用する。開始日前のSUMが繰越、対象期間のSUMを加えたものが期間最終残高。範囲に0件でも繰越を表示する。
- 初回の最大rowidをsnapshotとして固定し、100件ずつ全ページを読む。途中でバックデートされた新規入金が追加されても、その表示・印刷には混ぜない。最新に更新すると新しいsnapshotになる。
- ブラウザ側でも件数、繰越＋各deltaと各行balance、期間最終残高を照合する。不一致なら表示/印刷を止める。
- 日付不明・非安全整数等の不整合は409で表示を止め、元の履歴を変更しない。legacy-opening、旧データの日時注意、過去の負残高は注意表示のまま保存内容を出す。
- future incremental print用にentry ID・snapshot rowid・順序定義・sourceを返す。今回、印刷済みフラグや差分印刷UIは保存しない。

## 権限

- HOMEの既存セッション・アプリ許可・家庭メンバー・稼働済み通帳を検証。
- 子どもは本人の通帳だけ。既存の姉妹ポイント共有がONでも、今回のbook APIは姉妹の全履歴を返さない。
- 同家庭の保護者（有効なowner/admin、子ども区分でもchildren登録でもない）は同家庭の本人/子どもの通帳を選択可能。
- 通常の祖父母のプレゼント申請許可は通帳閲覧権にならない。本人の大人通帳があれば自分の分だけ表示できる。
- account/household/afterの書き換えで別人・別家庭の履歴は取得できない。口座一覧も同じ制限。
- 静的HTML/JS/CSSもHOME認証を通す。データ・印刷DOMをlocalStorage/Service Workerへ保存しない。戻る復帰/画面復帰で再取得し、印刷ボタン時も口座閲覧権を再確認。

## 表示と印刷

- 既存通帳カードのボタン→新ページ。ママ銀行・おさいふ帳・ポイント帳を切替可能、単位と入出金見出しを分ける。元のmemoを安全なtextとして表示し、プレゼントの申請者名・理由も既存memoから維持。
- 全履歴、年月、開始〜終了日。スマホ/タブレットは表の枠内を横スクロールし、画面全体は横にはみ出さない。
- A4横、余白は用紙内に10mm。1枚目は左が裏表紙、右が表紙。名前、発行日、期間、帳面名を表示。
- 2枚目以降は左右のA5パネルに本文を配置。各パネルに繰越/最終残高、本文ページ数、用紙番号、続きの案内。長文は途中を切り捨てず複数行・複数パネルへ分割し、金額/取引後残高はその取引の最終断片だけに表示。続きを独立した取引として重複計上しない。装飾のgift絵文字は紙面で省略し、本文の「誰からのプレゼント」は残す。
- 表紙は印刷面を外、本文は印刷面を内にして二つ折りし、用紙番号順に表紙ではさむ差し込み式。本文は用紙を1枚ずつ開いて読む。片面プリンターで可。中綴じ冊子の両面面付け機能ではない。
- A4/横/100％、ブラウザのヘッダー/フッターOFF。「冊子」「複数ページ/枚」は選ばない。window.printから印刷またはPDF保存。
- 印刷は白地・細い罫線中心。操作画面・HOMEメニューは印刷しない。印刷・PDF保存で台帳/口座を作成・更新しない。
