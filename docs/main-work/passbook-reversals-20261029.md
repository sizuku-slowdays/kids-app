## 操作と権限

保護者の「履歴を見る」→対象のプラス履歴の「この付与を取り消す」→名前・内容・日付・数量を確認し、理由を入れて確定。理由の初期値は「重複登録のため」。選んだ1件全額だけを差し引く。複数人一括登録でも他人の履歴、同時の現金/ポイントの別通帳、お手伝いの完了/当番は変えない。現金も不要なら現金履歴を別途確認して取り消す。

対象は既存 `manual` / `chores` / `chores-repeat` / `chores-retry` の正の入金/付与。過去日も対象。プレゼント承認・交換・お小遣い・利息・旧移行行・振替・負の取引・取消取引の取消は対象外。既存の入出金/ポイント調整は維持。

URL・認証・家庭の役割・他アプリの設定は変更しない。既存owner/adminゲートに加えSQLで有効な管理者所属を再確認する。子ども・一般大人・別家庭の書込は不可。子どもの履歴には取消結果のみ表示しボタンは出さない。

## 保存・安全性

DB schema/migration追加なし。既存 `passbook_entries` / `passbook_adult_entries` に `source_app='entry-reversal'`, `source_event=元の履歴ID` の逆符号行を追加。子どもは既存 `reversal_of` 外部キーも使用する。既存UNIQUE(account_id,source_app,source_event)と子どものreversal_of UNIQUEで二重差引き不可。元の履歴は編集/削除しない。追加行に理由・実行者・取消日時を残す。

POST `/api/passbook/entries/reverse` は `account_id`,`entry_id`,`reason` のみ受理し、差引額は元帳から決定。取消日現在の残高から、交換申請中の確保額を除いた範囲でのみ許可する。1 INSERT SELECTで残高確認と逆仕訳を原子的に実行。足りなければ409、日本語で案内。通信再試行/同時実行は一度だけ。画面も初回送信のID/理由を固定して再試行する。

過去の取引/利息を遡及修正しない。取消は現在日時で記帳し、今後の残高に反映される。旧手動のマイナス調整が既にあるかは自動推測できないため、利用者が履歴を確認して取消対象を選ぶ。こちらから本番の特定履歴を自動取消しない。
