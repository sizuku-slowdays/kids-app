# つうちょうへの切替

受領した現在のWorkerコードを元に、旧銀行/旧ポイントAPIを止めるゲートを追加。
D1/R2の設定・APP_PASSWORD・他アプリのコードを変更しない。
コード内のパスワードは環境変数参照だけで、Secretの値は含まない。

## 手順

1. home-worker のGitビルド成功を確認。取込済み残高・履歴を確認する。
2. mama-bank-api の「コードを編集」で mama-bank-api.js を配置しデプロイ。
3. otetsudai-api の「コードを編集」で otetsudai-api.js を配置しデプロイ。
   この時点では環境変数が未設定なら旧アプリは引き続き動く。
4. 両Workerの Settings → Variables and Secrets にテキスト変数を設定してデプロイ：
   Key: HOME_PASSBOOK_MIGRATED
   Value: 1
5. 以下のステータスが version:1 / retired:true となることを確認する。
   - https://api.cetus.fun/api/home-passbook-status （service:bank）
   - https://otetsudai-api.sslowdayss.workers.dev/api/home-passbook-status （service:chores）
6. ママで https://home-worker.sslowdayss.workers.dev/apps/passbook/ を開く。
   「引き継ぎ状況を見る」→「確認して本番のつうちょうを使い始める」。
7. HOMEに「つうちょう」が現れ、親には管理、子どもには残高/履歴/交換画面が開く。
   現金追加/出金、ポイント追加/調整はママ画面から行う。
8. 子どもの端末・ママの端末、未認証の別ブラウザで確認する。

## 操作の変更

旧お手伝い画面の当番ローテーション・完了登録・銀行同期は停止する。
現時点の新つうちょうではママがポイントと現金を登録する。
当番/完了登録そのものは新つうちょうへまだ移していない。
旧記録や商品/交換申請は非公開バックアップと新台帳に保持する。

## 切替を止める条件

旧APIが公開されたまま、片方だけ設定完了、バックアップ欠落/改変、
旧データの変更、新台帳の残高不一致では activation を作らない。
activation とHOMEアプリ表示の更新はD1の一つのbatchで行う。
本番開始の再実行は二重加算しない。

旧表示コピーの残高が本体と異なっても、そのコピーは取込元にしない。
取込済みハッシュにはコピーも含むため、取込後のコピー更新も検知して止める。

## 復旧

本番開始前に止まった場合、DBとR2バックアップは保持したまま原因を確認する。
本番開始後に旧Workerのゲートを外すと残高が二重管理になるため、元に戻さない。
旧アプリも新アプリも更新せず、確認済みのバックアップと新台帳から復旧を計画する。

## 検証

旧銀行APIのみ410、家計簿/学校の従来の認証ゲート維持、旧ポイント読み書き410、
未停止/差分あり/バックアップ改変では本番停止、照合成功時のみ利用開始、再実行は一回だけ。
この2本のWorkerはGitビルドで自動デプロイしない。Dashboardから配置する。
