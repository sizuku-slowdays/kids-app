# 翌月の収入見込みと楽天カード予算

2026-11-27 JST。開発ブランチ `feat/budget-income-outlook-20261127`。土台はHOME正本 `a3f8d12`。本番未反映。本番DB・実残高・個人の登録データにはアクセスしていない。

## 確認した原因

旧画面の `nextCardBudget` はブラウザ内で入金予定と月次収支を組み合わせて計算していた。継続的な給与・養育費の見込み設定がなく、未登録は加算されない。生活費未設定も0として暫定額を表示していた。手当の自動見込は既存 `monthlyBenefit` にあるが、給与・入金日・入金先の管理はない。

## 実装

- 計算を `src/budget-card-budget.js` のサーバー側の純粋関数にまとめ、既存summaryに `cardBudget` を追加。
- `incomeOutlook.rules`：給与・偶数月児童手当・奇数月児童扶養手当・養育費。初期候補は依頼の金額。初期状態は未保存で、明示保存するまで候補の見込みを有効にしない。入金日・入金先は勝手に補完しない。
- 給与は既存運用どおり予算月の前月入金を既定とし、給与・養育費は予算月に入金する設定にも切替可能。手当は実際の入金月で偶奇判定する。
- 月別の金額・日付・入金先・有効無効を `incomeOutlook.months[予算月]` に保存。個別設定解除で基本設定へ戻す。入金対象外の手当は画面でも対象外とし、加算しない。
- 基本設定変更は既存 `monthlyBenefit` と連動。旧手当設定からの変更も新しいルールへ反映し、月別見込みは既存月次収支にも反映。
- `fundReserves[月].carry` に次月へ残す額を追加。旧クライアントの保存では既存carryを消さない。過去に設定のない月は未設定として確認を求める。
- 金額・日付検証、本人限定API、expectedRevision・操作IDによる二重実行防止、既存の変更履歴/バックアップ/復元方式を再利用。DB schema/migrationなし。

## 計算と照合

計算用の月末繰越は、既存の `funds.monthEnd` から今月の生活費・確保額、積立確保済み額、今月の積立予定を控除する。給与などがこの金額に内包される場合は繰越部分から分けて表示し、収入欄で一度だけ計上する。上部の既存繰越指標は従来どおり未入金収入を含まないため、内訳には区別を明記する。

楽天カード引落予算＝繰越資金＋対象となる収入－翌月の口座支払い/他カード－生活費/用途別確保－翌々月への繰越確保－翌月の積立予定。

追加利用予算＝引落予算－楽天2枚の登録済み請求見込。負なら追加利用は0、不足額を別表示。

- カード請求は既存の仮額・CSV・確定額・定期支払い照合後の `projected` を使用。カード払い固定費を口座支払予定へ重ねて加算しない。振替を総支出にしない。
- 登録済みの収入の名称/カテゴリと入金月を照合し、実績を優先。実績の金額や日付が見込みと違っても見込みを重ねない。予定の確定・取消も現在の記録から再計算。
- 実績と未処理予定が併存、複数の手当予定、同額の未分類収入など照合が曖昧なら確認事項として利用可能額を出さない。既存取引・予定を自動削除しない。
- 名称/カテゴリに情報がなく金額等も異なる未分類の入金を、特定の給与だと断定できない。収支側で適切なカテゴリ/名称を設定する必要がある。開始残高の内訳も推測しない。
- 入金予定日・口座が欠ける場合は日別/口座別判定が不完全であると明示。予定日を過ぎた未入金額では利用可能額を出さない。
- 引落日の不足は既存 `projectAccountMonth` を再利用し、予算用見込みを一時的な入力として合成する。同日入金が引落に先行するとは決めつけない。口座残高は更新しない。
- 確保額・請求月・明細照合など重要項目が未設定なら `算出不可／要確認`。見込み収入に依存する表示は常に暫定。

## 画面と設定

HOMEの既存繰越カード内に、給与/手当/その他収入/総資金をPCで2列、スマートフォンで1列表示。引落予算・請求見込み・大きい追加利用予算を続けて表示する。詳細は折りたたむ。初回の「収入見込みを設定」、設定後の内訳内「収入見込みの基本設定」「この月だけ収入を変更」から操作する。生活費と繰越確保額は既存フォームへ統合。
