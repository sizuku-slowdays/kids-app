# 本番準備の手順（まだ実行しない）

1. 利用者が設計・保存期間・運営者と窓口・ドメイン・試験参加家庭を確認する。
2. HOMEから独立したD1/R2を新規作成する。既存home-db/notification-center-db/home-privateは選ばない。
3. 非公開R2設定、利用プランと画像処理CPU・メモリ・費用を確認。Freeで可能か未確認なので、画像処理込みの利用可否を事前測定する。無断の有料化・不安全な画像処理省略は禁止。
4. 専用の本番wranglerを別ファイルに作り、実ID/ドメイン/Secretを設定。devでは実IDを使わない。
5. 本番環境の変更・公開は利用者の承認後。初回は登録/招待を無効のまま新規DBへ0001を適用・非公開ステージングで試験。既存Workerのコード貼替は不要。
6. HTTPS/iPhone/Android/PC、PWA追加、親子4アカウントと複数端末、時間境界、失効、既読、画像を実機確認。
7. 専用cleanup Cron（例:1時間ごと）を設定。rawアクセスログの本文/token記録禁止、ログ保存/アクセス権を確認。R2の削除再試行、削除対象の100件ページ分割を確認。
8. 新DBエクスポートとR2の非公開バックアップ・復元を専用テスト環境で確認。backup manifestに件数/hash/時刻を残す。SQLや写真をGit/チャットへ貼らない。
9. 2家庭限定で初期登録コード/招待を有効化する。コード/招待URLそのものは運営側から勝手に相手へ送らない。
10. 動作確認後にだけ一般公開の可否を再判断。販売対応/国外利用の法令評価は別。
