# カレンダーのHOME本人連携

既存の所有者限定版 calendar-worker を基に、HOMEのセッションを毎回照会する認証を追加しました。予定・所有者ID・個人/共通設定は書き換えません。追加の連携テーブルだけを作ります。

## Cloudflareで行うこと

1. `calendar-worker` の Bindings で Service binding を追加します。Variable name は `HOME_AUTH`、Worker は `home-worker`。既存の `DB`・通知サービス・変数はそのまま保持します。
2. このフォルダーの `calendar-worker.js` 全文を `calendar-worker` のコードへ貼り付け、Deployします。HOME側の `CALENDAR_SERVICE` は作業ブランチの設定から自動で追加されます。
3. HOME管理者として `https://cetus.fun/wagaya/apps/calendar/` を開き、連携する家庭を選びます。
4. HOMEのママのアカウント → 既存カレンダーのママ、というように本人を明示して連携します。既存本人がいない利用者は「新しく作る」を選びます。他人の既存アカウントを選ばないでください。
5. 各利用者のHOMEログインで本人名・個人予定・共通予定を確認してから、HOMEのカレンダー表示チェックを戻します。

最初の連携が保存されると、家族カレンダーの旧ログイン経路は停止します。既存アカウントと予定の削除・再登録は不要です。本人連携は一対一で、既に連携した本人の変更は自動で行いません。からだカレンダーは既存の認証のままです。

## 保護

- Cookieセッションの本人情報をHOMEへ照会し、失効・利用権限・家庭所属を検査します。
- クライアントの旧Bearerトークン、Googleトークン、申告ユーザーIDでは本人を切り替えません。
- 既存の個人カレンダーは所有者本人だけ閲覧します。共通カレンダーはこの家庭の連携済み利用者が閲覧します。
- 予定の追加・変更・削除、カレンダー削除は既存の所有者IDで検査します。
- 未連携・別家庭・失効済みセッションの場合は予定を返しません。
- 応答は `private, no-store`。別タブでHOME利用者が変わった場合も画面を閉じて再取得します。

別家庭への展開時は、この既存カレンダーDBの家庭紐付けを流用せず、別のカレンダー保存先またはデータのグループ権限を用意します。この段階で別家庭を既存の共通予定へ自動的に入れることはありません。
